On go-template, a props member whose type is an inline intersection (`props: { data: A & B }`) now gets a generated struct with the merged members of every constituent, so its member reads (`props.data.label`, `props.data.at.getUTCFullYear()`) render the values instead of an empty string. Before, the member was an `interface{}` field holding the source-keyed map, which a capitalised member read could not find. The member may sit on an inline props type, a props interface, a destructured parameter, a named object type or an array element, and may be optional. An intersection whose properties are not its whole key set (a constituent with an index signature or a method, a mapped type, a generic, a `Record`, `any`, a constituent declared elsewhere) or whose members cannot be reconciled keeps the source-keyed map, and its member reads now go through `bf_get`, so a key no property declares (`props.data['extra']`) still reads. An inline object prop type with an index signature is kept as a map the same way. A whole value passed into a child's generated struct field (`<Show data={props.data} />`) is converted with `bf.Coerce`, so a prop typed by an inline object type or intersection can be forwarded to a child that declares its own. Phase 1 records `openMembers` on an object type literal and a type definition that declares a non-property member or type parameters. A destructured member typed as an intersection of same-file object types now carries that intersection as its `ParamInfo.type`, as the `props`-object form does. The new `inlineIntersectionMembers` export returns the merged members.
