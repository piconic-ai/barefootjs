A signal seed, memo body or component const the server render reads, and a child prop value, that applies an operator no template lowers (`typeof x`, `a ** b`, `~a`, a bitwise or shift operator, `in`, `instanceof`) is now refused with BF101 on every template adapter. Before, it rendered empty (`null`, `undefined` or `0` on some adapters) where Hono renders the computed value, with no diagnostic; a child prop passed such an operator in place was already refused everywhere except Go. The operator may sit directly in the declaration, in a callback it runs (`items.filter(t => typeof t === 'string')`), in a memo another read reaches, in a block-bodied memo whose single statement returns it (`() => { return typeof props.x }`), or in a member of an object literal a memo returns (`() => ({ kind: typeof props.x })`). A component const object literal is refused only when a read reaches the member that applies the operator: `{o.n}` beside `kind: typeof props.x` still renders as before. A block-bodied memo with more statements is not refused yet. `/* @client */` on the read defers it to the client, except for a value a child prop reads, which renders on the server whatever directive the prop carries. An operator in a function that is stored and never called is not refused.
