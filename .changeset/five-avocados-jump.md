Fix the Go template adapter leaking a stray newline between text and an immediately-following rendered child component. Every compiled `.tmpl`/`.gotmpl` file wraps its body in `{{define "ComponentName"}}\n...\n{{end}}\n` for source readability; Go's `text/template` has no environment-level auto-trim option (unlike Jinja's `trim_blocks`/`lstrip_blocks`), so those template-source newlines rendered literally. A child rendered via `{{template "Child" ...}}` therefore returned output starting (and ending) with a literal `\n`. Normally invisible (it collapses away between two HTML tags), it surfaced as a real newline the moment the preceding sibling was text rather than a tag — e.g. an `AccordionTrigger`'s label text immediately followed by its `ChevronDownIcon`, exposed once #3237's JSX-whitespace fix stopped Hono from emitting its own (incorrect) trailing space in that same spot. `GoTemplateAdapter.generate()` and `generateScriptRegistrations()` now use explicit `{{define "X" -}}` / `{{- end}}` / `{{end -}}` trim markers to strip the compiler's own template-formatting whitespace around the define body without touching interpolated values or literal HTML/text content.
