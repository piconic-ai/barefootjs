Fix #2723: a semantically-inert `const x__alias = x` hop between a destructured prop and its use site (exactly what the `alias-props` mutation sweep inserts, #2481) silently dropped the attribute's `createEffect`, and — independently — broke recognition of a `{...rest}` spread once the rest parameter was aliased too, dropping `applyRestAttrs` and folding the spread into the SSR template's `spreadAttrs({...})` merge under the alias's name instead. When the dropped effect was `init`'s only content, the whole function collapsed to `function initX() {}`, taking the `$`/`createEffect`/`applyRestAttrs` imports with it — so any caller-passed attribute (`id`, `aria-*`, `for`, …) silently never reached the DOM, surfacing as hydration removing real attributes.

Both defects were the same shape: `ir-to-client-js`'s Phase 2 re-derives reactivity/spread-source identity from expression text without following a local-const alias chain the way Phase 1's `isPropsReference`/`isSignalOrMemoReference` already do against `ctx.patterns.constants`. Fixed by porting that same constant-chain walk onto Phase 2's `ClientJsContext.localConstants` — `needsEffectWrapper` (`ir-to-client-js/reactivity.ts`) now recurses through a local-constant alias to the prop/signal/memo it ultimately reads, and a new `resolveRestSpreadOrigin`/`resolveRestSpreadNames` (`ir-to-client-js/prop-handling.ts`) resolves a spread's source expression through the same kind of alias chain onto the rest parameter or props object. A third, related gap surfaced once the first two were fixed and a rest-parameter alias's own declaration stopped being dead code: `rewritePropsObjectRef`'s fallback for destructured-prop components previously only recognized a rest binding literally spelled `props` (an accident of convention every real UI component happened to follow) — it now also resolves the analyzer's actual `restPropsName`, so `const rest__alias = rest` correctly becomes `const rest__alias = _p` regardless of what the rest parameter is named.

None of this reintroduces ad-hoc loop-scope tracking (`BindingScope` is unrelated — it resolves loop/callback bindings, not a component-body `const` aliasing a prop) or a new tracking structure — every fix reads the existing per-component `ctx.localConstants` list Phase 2 already carries.
