The client-side template now evaluates a const whose initializer can give a different value each time it runs (it builds an object or array, constructs, calls, or creates a function anywhere: `{ k: 'v' }`, `mk()`, `new Date(0)`, `'x' + Math.random()`, also when it reads a prop or a signal) once per template evaluation, and every read in that evaluation sees the one value, as the server render does. The template wraps its body in `((__bf_const_B) => \`…\`)(<value>)`, where the value is what a read at the top of the template inlined before. Two reads of an object const are now the same object on a client mount (`B === B` rendered `false`), and two reads of a sampling const now see one sample. A const whose initializer only reads names and combines them with operators is still inlined at each read, byte-identical. A const aliasing such a const (`const C = B`) is still inlined with the value it resolves to, so `C === B` remains `false` on a client mount (`module-const-alias-identity`). `ConstantInfo.freshPerEvaluation` marks a const the template binds.
