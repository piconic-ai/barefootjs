Fixed a leak in `@barefootjs/client/runtime`'s CSR mount path: `render()` (and the other `template()` call sites — `createComponent()`'s by-name and `ComponentDef` paths, and the conditional-branch template evaluator in `insert.ts`) called a component's compiled `template()` function before `init()` ran and with no reactive owner in scope. When the JSX read a local bound to an imported helper's call (`const value = watch(props.source); return <p>{value()}</p>`), the compiler inlines that call verbatim into the template so it has an initial value to render — by design, matching Hono SSR's contract. If the helper created a signal and registered `onMount`/`onCleanup` (the natural shape for bridging outside state into a signal), that registration had no owner to release it: `onMount` ran synchronously and `onCleanup` was a permanent no-op, so the subscription outlived the component for the life of the page.

A `template()` call now runs inside a throwaway reactive root that is disposed immediately after it returns, but only when no reactive owner is active yet — giving that specific call a real owner so anything it creates is torn down before `template()`'s result is used, matching the retained instance's own `init()` (run moments later) creating the real, persisted signal. When a real owner is already active (the common case — a `.map()` row's per-item root, or a component's own `init()` root), the call is instead just isolated from the ambient tracking context (`untrack()`), so anything it creates stays owned by that real, already-persistent owner instead of being disposed the instant the call returns. This matters for a `renderNode`-style prop (an inline JSX-returning arrow passed as another component's children, hoisted into a synthesized component): invoking it from inside a conditional runs that child's own `materializeComponent`/`initFn` synchronously as part of producing the branch's template result, with no later "real" init to hand off to — unconditionally wrapping that call in a disposed-immediately root tore down the child's reactive effects before a single signal update could ever reach them (found via `site/ui`'s xyflow Highlight-Depth demo, whose per-node `--node-glow` style effect fired once and then never again).
