Escape-by-default for client-JS HTML template holes (#2795). Whether a `${...}` hole in a compiled client template was escaped used to be an opt-in each builder remembered on its own — the `escapeInClientTemplate` IR flag, a pre-baked `escapeText(...)` string inside `templateExpr`, the `escapeLeafTextExpressions` rewrite pass, and a hand-written `escapeText` in `buildPreambleRegionPlans` — and a forgotten opt-in shipped raw text twice (#1694; #2765/#2792, the same miss in two builders). All four mechanisms are deleted. New `ir-to-client-js/safe-html.ts` introduces a compile-time nominal brand, `SafeHtml`, on JS expression strings that evaluate to already-safe HTML; `interp()` is the only way to write a hole and accepts `SafeHtml` only, so a builder holding a plain string cannot splice it. Named producers brand each known-safe construction at its source (`escapedText`, `branchSlotValue`, `childrenMarkup`, `joinedMarkup`, `renderChildCall`, `conditionalMarkup`, `mappedRowsMarkup`, `dangerousInnerHtml`), and one door, `spliceChildValue`, decides the producer for every child-position expression in all five builders — its last arm is `escapeText`, and no arm returns the input unwrapped. `markupSlotIdsOf()` (`markup-slots.ts`) replaces three copies of the initial-render markup-slot derivation and shares its writer-kind constant with `emit-reactive.ts`. The migration also closes a previously unreported member of the family: a module-scope string constant in text position (`const LABEL = 'a<b'; <div>{LABEL}</div>`) was constant-inlined into the bare-splice fallthrough unescaped. Emitted bytes change only for flatMap/preamble leaves (`escapeText((x))` → `escapeText(x)`) and the init-only-ref placeholder in a slotted position (`${escapeText('')}` → `${''}`). Backstopped by `client-template-escape-soundness.test.ts`: a TS-AST sound-or-loud ratchet over emitted templates with an empty, shrink-only hole set, pinning #1694, #2765/#2792 and the inlined-constant shape; it subsumes and replaces `text-slot-escaping.test.ts`.
