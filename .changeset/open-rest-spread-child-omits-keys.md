An open-type `{...rest}` bag spread onto a child component now reaches the child on the client as JS builds it (#3714): the caller's props without the keys the component destructured, merged with the call's explicit props in source order. `initChild` used to forward the caller's whole props object, so a destructured key (`title` in `function Card({ title, ...rest })`) reached `<Tag {...rest} />` as well, an explicit prop written before the spread (`<Tag tone="first" {...rest} />`) always won over the caller's value, and the registration template left the spread out, so a client mount rendered the child without any of the bag's keys. The same now holds in a conditional branch and in loop rows, which used to drop the bag. A rest bound in the component body (`const { title, ...rest } = props`) leaves out only the keys that destructure takes; spread onto an element, it used to leave out every key the props type declares. A call that spreads the rest bag or the props object and has JSX children (`<Child {...rest}>{children ?? 'fallback'}</Child>`) now hands the child's client init those children, written last as JSX does; it used to hand over the caller's own `children` instead.
