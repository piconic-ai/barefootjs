A const initialized by an immediately invoked zero-param arrow whose expression body gives the same value each time, writes nothing, holds no function and reads no `let` or `var` it resolves to (a const or a prop named like an unrelated `let` is fine; a key or member name `arguments` reads nothing) (`const B = (() => ({ k: V }))()`, also nested, or under parentheses, `as`, `satisfies`, `!` or `<T>` at the callee or the result, module or component scope) now holds that body for every consumer, as `const B = { k: V }` does. Its reads render on the template adapters as they do on Hono, and on a client mount, where a template adapter rendered them empty before (also when the arrow read no other module const) and a client mount rendered a component const of that shape empty. A const whose initializer calls a function literal in place in any other form, at any depth (a block body, an argument, a body that constructs, samples or writes, a body returning a function, a call under an operator, in a conditional, a template literal, an array or object literal, an array iteration callback or the default of its parameter, or any such call in a `let`), is now refused with BF101 on the template adapters when the server render reads it, where its reads rendered empty or failed the render; `/* @client */` defers a markup read. `ConstantInfo.callsFunctionLiteral` marks such a const. The applied-arrow decision the client template uses moved to `applied-arrow.ts`; it no longer accepts a body that builds JSX, writes, or reads `this`, `arguments`, `super` or `new.target`, nor an optional call.
