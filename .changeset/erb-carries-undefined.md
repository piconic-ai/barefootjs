---
"@barefootjs/erb": minor
---

The ERB adapter and its Ruby runtime (the `barefoot_js` gem) now carry JS `undefined` apart from `null` (`spec/js-undefined-value.md`, rollout step U4). Host `nil` is JS `null`; JS `undefined` is `BarefootJS::UNDEF`, a frozen singleton whose `nil?` is true and which prints as `''`. A missing key, an out-of-range index, `.at()` / `.find()` with no result, the `undefined` identifier (`bf.undefined` in a template), `?.` over a nullish receiver (`bf.get_opt`), an optional or untyped field read (`bf.get`), a template var the host did not set and an omitted declared prop read as `UNDEF`. `String()` / template literals / `+` print it as `"undefined"` (`null` as `"null"`), `Number()` and arithmetic read it as `NaN` (`null` as `0`; an unproven `-` / `*` takes the new `bf.sub` / `bf.mul`), `x === null` / `x === undefined` are strict tests (`bf.is_null` / `bf.is_undefined`; `x == null` is `bf.is_nullish`), `JSON.stringify` and the `bf-p` / scope-comment payloads drop an `undefined` member and write an `undefined` element as `null`, `includes` / `indexOf` tell the two apart, a sort puts `undefined` last, and an optional method argument (`slice` end, `join` / `split` separator, `padStart` pad, `at` index, …) takes its default only when it is omitted or `undefined`. A destructure default now applies only to an absent or `undefined` prop: an explicit `nil` keeps `null` (`BarefootJS::Context.derive_vars_from_defaults`). The gem adds `BarefootJS.undefined?` / `null?` / `nullish?` and, on `BarefootJS::Context`, `undefined`, `is_undefined` / `is_null` / `is_nullish`, `get_opt`, `sub` and `mul`.

Migration: a host that passed `nil` to mean "unset" now gets JS `null` semantics (`'btn ' + c` renders `btn null`, and a destructure default no longer applies). To leave a prop unset, leave its key out of the props Hash; to pass a prop that is present and `undefined`, pass `BarefootJS::UNDEF`. Ruby treats `UNDEF` as truthy: host code that tests a value it got back from the runtime should use `BarefootJS.nullish?` rather than `if value`.
