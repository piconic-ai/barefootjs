Fix #2737: a local `const` alias of the whole props object (e.g. the SolidJS-style `const props__alias = props`) leaked the pre-rewrite name into a component's CSR template. Constant inlining correctly substitutes the alias with `props`, but as a parenthesised receiver (`(props).label`) — and `html-template.ts`'s four template-builder closures (`irToComponentTemplateWithOpts`, `generateCsrTemplateWithOpts`, and the flatMap/loop preamble transforms) each ran their own `\bpropsObjectName\.` regex to rewrite `props.x` → `_p.x`, which requires the name to be immediately followed by `.` and so left `(props).x` untouched. The init body's own rewrite (`rewritePropsObjectRef`, an AST walk over real TypeScript) never had this gap; the four template sites now call that same function instead of their own regex copies, and `csr-substitute.ts`'s now-redundant `applyPropsRewrite` regex sibling is deleted. `rewritePropsObjectRef` also gained an optional `enclosingScope` (`BindingScope`) so a `.map()` row parameter that happens to share the outer props object's name is correctly left un-rewritten (it shadows, per CLAUDE.md's `isBound()` shadow-guard convention) rather than skipped by having two separate rewrite implementations disagree on when to stop.
