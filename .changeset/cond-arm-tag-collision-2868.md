Fix #2868: a reactive conditional branch (`{cond ? <A/> : <B/>}`) inside a keyed `.map()` row could corrupt its own re-render `template()` HTML when a branch's root tag name collided with the enclosing loop's item/index parameter name (e.g. `<i>` became `<i()>` when the loop declared `.map((item, i) => ...)`). The corruption came from re-wrapping the branch's already-assembled HTML string with a word-boundary regex meant to turn a bare loop-param/index reference into an accessor call — that regex can't tell a real identifier reference apart from a tag name spelled the same way, since `<`/`>` are non-word characters.

Every loop-param-wrapped HTML string is now rendered against the full loop-param chain structurally, at IR-render time (`irToHtmlTemplate`'s `loopParams`), instead of being wrapped a second time afterward: removed the post-hoc `wrapLoopParamAsAccessor` calls over branch-arm HTML in `build-reactive-effects.ts`, `build-loop-child-arm.ts`, and `build-lazy-row.ts`. `collectLoopChildConditionals` now accepts the full ancestor loop-param chain (not just the immediate loop's own), fixing an adjacent gap where a conditional inside an inner `.map()` couldn't reference an *outer* loop's item/index in its branch HTML at all. The plain-row eager template (`build-plain-row.ts`) gets the same treatment via a new `templateIndexed` field — a second structured render with the index wrapped, computed alongside the existing item-only `template` — replacing its own post-hoc `wrapIndexParamAsAccessor(loop.template, ...)` call.
