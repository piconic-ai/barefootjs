The Mojolicious and Xslate adapters and their shared Perl runtime (the `BarefootJS` CPAN dist) now carry JS `undefined` apart from `null` (`spec/js-undefined-value.md`, rollout step U5). Perl's `undef` is JS `null`; JS `undefined` is `$BarefootJS::UNDEF` (new `BarefootJS::Undefined`), a singleton that is false in boolean context, prints as `''`, numifies to NaN, and is `defined` in Perl's sense. A missing key, an out-of-range index, `.at()` / `.find()` with no result, the `undefined` identifier (`bf->undefined` / `$bf.undefined()` in a template), `?.` over a nullish receiver (`bf->get_opt`), an optional or untyped field read (`bf->get`) and an omitted declared prop read as `UNDEF`. `String()` / template literals / `+` print it as `"undefined"` (`null` as `"null"`), `Number()` and arithmetic read it as `NaN` (`null` as `0`; `subtract` / `multiply` / `divide` / `mod` coerce through JS ToNumber), `x === null` / `x === undefined` are strict tests (`is_null` / `is_undefined`; `x == null` is `is_nullish`), `??` coalesces both (`keep_nonnil`), `JSON.stringify` and the `bf-p` / scope-comment payloads drop an `undefined` member and write an `undefined` element as `null` (the walk runs before JSON::PP / Mojo::JSON, so the encoder never sees `UNDEF`), `includes` / `indexOf` tell the two apart, a sort puts `undefined` last, and an optional method argument (`slice` end, `join` / `split` separator, `padStart` pad, `at` index, …) takes its default only when it is omitted or `undefined`. A destructure default now applies only to an absent or `undefined` prop: an explicit `undef` keeps `null` (`BarefootJS::_derive_stash_from_defaults`, and the Mojolicious plugin's root seed). The runtime adds `BarefootJS::Undefined::is_undefined` / `is_null` / `is_nullish` and, on the `bf` object, `undefined`, `is_undefined` / `is_null` / `is_nullish`, `get_opt` and `keep_nonnil`.

Migration: a host that passed `undef` to mean "unset" now gets JS `null` semantics (`'btn ' + c` renders `btn null`, and a destructure default no longer applies). To leave a prop unset, leave its key out of the props hash or stash; to pass a prop that is present and `undefined`, pass `$BarefootJS::UNDEF`. `UNDEF` is `defined` and `//` keeps it: host code that tests a value it got back from the runtime should use `BarefootJS::Undefined::is_nullish` rather than `defined` / `//`.
