A read of the component's own `children` prop through another binding is now treated as the children prop, the same as `{children}`. This covers a binding renamed in the parameter destructure (`function Box({ children: kids })`), a const alias of it (`const c = children`, `const d = c`), and a `.children` read through a const alias of the props object (`const p = props; p.children`). In the client template these reads used to escape present children into visible `&lt;span&gt;` text, either through a reactive text slot (the renamed binding and the props-object alias) or through the escaped-text path (the const alias of the children prop); they are now spliced as markup, and only a `??` / `||` fallback is escaped. A fragment root that only passes such a read through (`<>{kids}</>`) is transparent like `<>{children}</>`. On Go templates, the renamed binding reads the `Children` field that the parent's children fill, where it used to read a separate `Kids` field that was never set, so present children were dropped. The SSR output of a renamed children read no longer carries text-slot markers. A local named `children` that binds another prop (`{ label: children }`) is now read as that prop. An alias resolves where it was declared, so a loop row that shadows a name its initializer reads (`rows.map(props => …{c}…)` for `const { children: c } = props`) no longer turns the children into escaped text. On Go templates, a local named `children` that binds another prop is held in that prop's own field (`Label` for `{ label: children }`), so it no longer shares the `Children` field with the children prop; a `props.<key>` read takes the field of the prop with that key, not of a body local named like the key; and a `key` (or other attribute) that reads a loop row named like a nillable prop no longer tests the prop's field inside the row. An optional attribute's omission guard now tests the same field the attribute's value reads, so `title={children}` for `{ label: children }` is gated on `Label`, not on the children payload.
