Fixed a `ReferenceError` thrown on every click for an event handler inside a nested `.map()` over static (module-level `const`) arrays, when the handler closes over the INNER loop's own param (e.g. `CHOICES.map(choice => <button onClick={() => setPicked(`${group}${choice}`)}>...</button>)`). Static arrays hydrate their outer loop via a plain `forEach` rather than `mapArray`, so their delegated click listener resolves the loop item positionally (`static-index`) instead of by key. That resolution only ever declared the OUTER loop's item, never the inner one, so a handler reading the inner param read an undeclared identifier and the click silently did nothing (a radio group's `aria-pressed`/`aria-checked` never flipped). The delegated dispatcher now also resolves each nested loop's item — scoping a lookup to the previously-resolved row and reading the clicked element's position within it, the same way the existing static-nested-loop hydration path (#2798) already recovers a nested row — mirroring the keyed delegation path's existing (`data-key-N`-based) nested-loop support. Closes #3240.

Also fixed a follow-up silent-divergence bug in that same nested positional resolution: it never subtracted a nested loop's own leading-sibling offset (a static element, or another loop, preceding the inner `.map()` inside its container), so any such offset silently resolved the click to the WRONG item instead of throwing — e.g. `<div><span>hdr</span>{CHOICES.map(...)}</div>` picked `CHOICES[1]` when the first button was clicked. The delegated-event `NestedLoop` chain now resolves the same static-sibling-count offset the hydration-side `NestedLoop` (`collectInnerLoops`) already applies, via the shared `resolveLoopOffset`.
