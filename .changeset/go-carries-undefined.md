**Breaking change** of the generated Go API and the Go runtime (released as a minor under the 0.x convention): read the migration guide in the [Go Template Adapter docs](../docs/core/adapters/go-template-adapter.md#migrating-to-bfopt) before upgrading.

The Go template adapter and its Go runtime (`github.com/barefootjs/runtime/bf`) now carry JS `undefined` apart from `null` (`spec/js-undefined-value.md`, rollout step U8).

Go's `nil` is JS `null`, a typed nil slice, map or pointer included (`String()` prints it as `"null"`, a text child renders nothing); JS `undefined` is the new `bf.Undefined` (a typed nil that prints as `""`), created only where JS reads `undefined`: a missing key or field, an out-of-range index, `.at()` / `.find()` with no result, `?.` over a nullish receiver, the `undefined` identifier (`bf_undefined`) and an omitted prop. `String()` / template literals / `+` print it as `"undefined"` (`null` as `"null"`; `String(x)` is now `bf_to_string`, `Number(x)` `bf_to_number`), `Number()`, arithmetic and the `Math` helpers read it as `NaN` (`null` as `0`), `x === null` / `x === undefined` are strict tests (`bf_is_null` / `bf_is_undefined`; `x == null` is `bf_is_nullish`), `JSON.stringify` (`bf.JSON`, which now returns `bf.Undefined` for an `undefined` argument) and the `bf-p` payload drop an `undefined` member and write an `undefined` element as `null`, `includes` / `indexOf` / `startsWith` tell the two apart, a sort puts `undefined` last, and an optional method argument (`slice` end, `join` / `split` separator, `split` limit, `padStart` pad, `endsWith` position, `flat` depth) takes its default only when it is omitted or `undefined`. A destructure default now applies only to an omitted or `undefined` prop: an explicit `null` keeps `null`. A `{...props}` spread onto a child carries a key whenever the caller passed it, `null` and `undefined` included. An explicit attribute (`tone={row.tone}`) always passes its key, `undefined` for a field the row omits.

Generated code: a prop whose type admits absence or `null` (an optional, `| null`, `| undefined` or `unknown` prop) is a `bf.Opt[T]` field on `<Name>Input` (`json:"<name>,omitzero"`), with the four JS states: omitted (the zero value), `bf.Undef[T]()`, `bf.Null[T]()` and `bf.Some(v)`. `Passed()` is JS `'k' in props`, `V()` the JS value and `Value()` the held value; `encoding/json` decodes `null` to `Null` and a missing key to omitted. An optional field of a generated struct (a loop row's `tone?: string`, `tags?: string[]`, or `meta?: Meta` as `bf.Opt[*Meta]`, which was a `*Meta`) is a `bf.Opt[T]` too, which templates read as its JS value (`bf_js .Tone`, the new `bf.JSValue`); a generated `{{range}}` over a value that may be `undefined` goes through the new `bf_iter`. A parent builds a child's Input field through the new `bf.Coerce`. The runtime adds `bf.Opt`, `bf.Some`, `bf.Null`, `bf.Undef`, `bf.OptOf`, `bf.Coerce`, `bf.Undefined`, `bf.IsUndefined` / `bf.IsNull` / `bf.IsNullish`, `bf.GetOpt`, `bf.Has`, `bf.JSValue` and `bf.Iter`, and the template functions `bf_undefined`, `bf_is_undefined`, `bf_is_null`, `bf_is_nullish`, `bf_get_opt`, `bf_has`, `bf_js` and `bf_iter` (`bf.Iter`).

Breaking: host code wraps each optional or nullable prop it passes in `bf.Some(...)` (`bf.Some[float64](0)` for a numeric constant), and leaves a field out to leave the prop unset; a `bf.Null[T]()` means JS `null`. The `.some(item => item.field)` helper `bf.Some` is renamed `bf.SomeField`. `bf.JSON` returns `(any, error)`; `bf.Join`, `bf.Split`, `bf.PadStart` / `bf.PadEnd`, `bf.Contains`, `bf.StartsWith` and `bf.EndsWith` take their separator / search / pad argument as `any`. `bf.Sub`, `bf.Mul`, `bf.Div`, `bf.Mod`, `bf.Floor`, `bf.Ceil`, `bf.Round`, `bf.Abs`, `bf.Min` and `bf.Max` coerce through JS ToNumber.
